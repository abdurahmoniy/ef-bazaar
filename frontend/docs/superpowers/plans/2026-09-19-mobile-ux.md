# Mobile UX Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development for bounded implementation and review tasks.

**Goal:** Implement the approved mobile audit improvements across marketplace, gallery, chat, listing creation, profile, and wallet.

**Architecture:** Keep existing Next.js/React components; extend wallet history with an optional trade association using existing ledger keys. Add focused helpers only for behavior that needs regression coverage. Public image caching must remain separate from private authenticated responses.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind, Vitest.

- [x] Marketplace/media: inspect optimizer bypass, deliver responsive thumbnails with safe fallback; expose title/facts, sorting and 44px controls; reduce prefetch; retain scroll state; inline touch gestures and image feedback.
- [x] Chat: trace proposal API contract; fix incorrect handling, bounded foreground polling and visible retry, draft persistence and keyboard behavior. Test HTTP status interpretation and polling recovery.
- [x] Listing: require explicit service-link answers; validate files with useful errors and limits; restore drafts safely; retain net-price preview. Test unset versus false and mixed file rejection.
- [x] Profile/wallet: correct mailbox count/labels, tasks/promotions hierarchy and linked state; unclipped amount input, withdrawal eligibility and transaction context. Test count/eligibility logic.
- [x] Shared shell: browser zoom, stable authenticated navigation, route skeleton, reduced motion and unobstructed support.
- [x] Verification: run relevant Vitest files per change, full test suite, typecheck, lint, production build; inspect local mobile views; spec review then code quality review; document external cache/device checks.

Regression tests precede behavioral changes. Use existing tests for reversible layout/copy changes rather than adding source-mirroring tests. Review files in each task before editing. No deployment is part of this plan.

Execution details and external limitations: [verification report](../mobile-ux-verification.md). Wallet transaction IDs and authenticated trade links are implemented, including the compatible payment-service association field. CDN rules and physical multitouch remain external checks.
